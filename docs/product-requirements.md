# 说猫语 产品需求文档

## 1. 文档概述
- 产品名称：说猫语
- 产品类型：iOS 宠物互动应用
- 文档目标：明确 MVP 阶段的产品范围、交互方向与 UI 风格要求，为后续设计与开发提供统一依据。

## 2. 产品背景
养猫用户经常会遇到两个典型问题：
- 听到猫咪叫，但无法判断它是饿了、烦躁、害怕还是想互动。
- 想主动和猫咪交流，但不知道怎样的声音和语气更容易引起回应。

市面上很多宠物工具产品偏功能展示或娱乐化，缺少兼顾情绪价值、实用表达和视觉审美的产品。说猫语希望从“沟通”和“陪伴”两条线切入，提供一个既实用又让人愿意反复打开的产品。

## 3. 产品目标
### 3.1 业务目标
- 建立清晰的产品记忆点：把“猫语翻译”做成核心心智。
- 提升用户日常使用频次，形成录音、识别、互动的轻量习惯。
- 通过高辨识度 UI 提升分享意愿与口碑传播。

### 3.2 用户目标
- 快速理解猫咪当前可能的情绪和需求。
- 用更有趣、更贴近宠物互动的方式与猫咪交流。
- 在使用过程中获得陪伴感、治愈感和被理解感。

## 4. 非目标
- 不承诺专业兽医级诊断能力。
- 不在 MVP 阶段构建复杂社区或电商体系。
- 不把产品做成偏硬核参数分析工具。

## 5. 目标用户
### 5.1 核心用户画像
- 年龄：18-35 岁。
- 城市：一二线及新一线城市为主。
- 特征：长期养猫、愿意为宠物花时间和情绪价值、对产品颜值与体验敏感。
- 偏好：喜欢可爱、温暖、软糯的视觉风格，愿意分享宠物相关内容到社交平台。

### 5.2 代表用户
- 用户 A：独居白领，养一只英短，把猫当家人，希望更懂它的情绪。
- 用户 B：大学生铲屎官，喜欢记录日常，希望有趣地和猫互动。
- 用户 C：新手养猫用户，需要简单易懂的情绪与需求解释。

## 6. 典型使用场景
### 6.1 场景一：猫突然频繁叫
- 用户打开应用，点击录音。
- 系统分析叫声后给出“可能在索要关注”或“可能对环境不安”等结果。
- 用户看到建议，例如“先观察周边噪音或尝试安抚互动”。

### 6.2 场景二：用户想主动互动
- 用户输入“来吃饭啦”或“不要怕，我在”。
- 系统将文本转换为带情绪色彩的猫语音效。
- 用户播放后与猫咪互动，感受趣味反馈。

### 6.3 场景三：用户想要更可爱的陪伴体验
- 用户即使不做深度识别，也愿意打开应用查看可爱的首页、互动卡片和记录内容。
- 应用需要具备足够强的视觉吸引力与情绪价值。

## 7. MVP 功能范围
### 7.1 P0 功能
#### A. 猫语转人话
- 支持麦克风录音。
- 支持上传本地音频作为补充方案。
- 完成基础音频分析并输出结果。
- 结果至少包含：情绪标签、需求标签、通俗解释、建议动作。

#### B. 人话转猫语
- 支持文本输入。
- 支持选择语气模板，如安抚、召唤、夸奖、陪玩。
- 支持生成并播放猫语音效。

#### C. 结果表达
- 结果不只展示分类标签，还需以自然语言解释“为什么会这样判断”。
- 结果页需包含下一步建议，避免“识别完就结束”。

### 7.2 P1 功能
- 历史记录：保存最近识别结果与互动文本。
- 收藏常用短语：收藏高频的人话转猫语内容。
- 分享卡片：将可爱的结果卡片分享给朋友或社交平台。

### 7.3 暂不进入 MVP 的功能
- 宠物社区。
- 多宠物家庭复杂档案系统。
- 会员订阅与付费内容体系。

## 8. 信息架构建议
### 8.1 首页
- 顶部品牌区：品牌名、Slogan、猫咪插画或动态装饰。
- 中部主操作区：录猫叫、说人话两个主入口。
- 下部轻内容区：最近一次结果、推荐互动短语、情绪小贴士。

### 8.2 猫语识别页
- 录音按钮置于视觉中心。
- 展示实时音波或录音状态反馈。
- 识别完成后进入结果页。

### 8.3 人话转猫语页
- 文本输入框。
- 语气选择器。
- 生成与播放按钮。

### 8.4 结果页
- 情绪卡片。
- 需求卡片。
- 通俗解释卡片。
- 建议行动卡片。
- 可选的“再试一次”与“保存记录”。

## 9. UI 视觉需求
### 9.1 视觉关键词
- 可爱。
- 治愈。
- 软糯。
- 轻盈。
- 陪伴感。

### 9.2 目标风格
- 面向“养宠女孩”的审美取向，强调温柔、细腻、精致。
- 整体氛围应像宠物生活方式品牌，而不是技术演示工具。
- 要让用户第一眼感受到“想打开、想截图、想分享”。

### 9.3 配色建议
- 主色：蜜桃粉、奶油白。
- 辅色：燕麦杏、浅咖、鼠尾草绿。
- 点缀色：珊瑚橘或焦糖色，用于按钮高亮或重点提示。
- 避免使用高饱和荧光色、强对比黑紫配色、冰冷科技蓝为主色。

### 9.4 组件风格
- 大圆角卡片。
- 柔和阴影。
- 低对比背景分层。
- 插画感图标或猫爪、耳朵、尾巴等轻量化装饰元素。
- 按钮应偏饱满、易点击，避免过细描边风格。

### 9.5 动效要求
- 录音时可有轻微呼吸感动画或音波动画。
- 页面切换与结果出现建议采用柔和的淡入、上浮、弹性过渡。
- 动效服务于可爱感和反馈感，不能影响核心操作效率。

### 9.6 排版要求
- 信息层级必须清晰，不能因追求可爱而牺牲可读性。
- 标题、结果标签、解释说明应有明确字重和字号层次。
- 结果区要避免大段密集文字，应以分块卡片方式呈现。

## 10. 交互体验要求
- 首屏 3 秒内让用户理解“这是做什么的”。
- 首次使用尽量减少学习成本，不依赖复杂引导。
- 核心按钮要大、明显、好点，适配单手操作。
- 录音、识别、播放都需要即时反馈，避免用户不确定系统是否在工作。
- 空状态、加载状态、失败状态都要有温柔且明确的提示文案。

## 11. 文案要求
- 用语要像一个懂猫、也懂用户情绪的陪伴型产品。
- 避免机械式提示，例如“识别成功”“分析完成”。
- 推荐文案风格示例：
  - “它今天好像有点想撒娇。”
  - “这段叫声像是在催你看看它。”
  - “试试用更温柔的语气回应它吧。”

## 12. 非功能要求
- 支持 iPhone 主流屏幕尺寸，优先保证移动端单手体验。
- 基础页面需保证流畅，录音与播放反馈及时。
- 结果展示需保证可读性和可访问性，避免过小字号与低对比文字。

## 13. 验收标准
- 用户能在首页清楚区分“猫语转人话”和“人话转猫语”两个主功能。
- 用户能在一次完整流程内完成录音、识别、查看结果。
- 结果页同时包含情绪、需求、解释、建议四类信息。
- 视觉风格明显区别于默认系统模板，具备可爱、治愈、养宠女孩风格特征。
- 整体界面不出现明显“技术后台感”或“演示稿感”。

## 14. 后续迭代方向
- 多只猫档案管理。
- 每日情绪记录与趋势卡片。
- 社交分享模板优化。
- 个性化猫语包与互动场景扩展。
